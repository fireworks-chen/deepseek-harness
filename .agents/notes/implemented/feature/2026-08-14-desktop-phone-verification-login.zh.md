# Agent Note: 桌面端手机号验证码登录

Status: implemented

[English](2026-08-14-desktop-phone-verification-login.md) | 中文

## Problem

Electron 外壳目前展示邮箱和密码表单，而目标用户端入口使用手机号和验证码。生产认证接口尚未提供，但桌面应用仍需呈现接近真实产品的登录页面，并提供稳定的集成点，使接入接口时无需再次重写渲染层。

《服务条款》和《隐私政策》共用一个随部署环境变化的网站根地址。若在渲染层重复写死测试地址，生产打包容易出错。账户菜单中的个人中心、团队管理和我的金币代表未来导航入口，但当前被渲染为不可交互的信息行。

## Decision

桌面登录表单使用已确认的手机号验证码布局：

- 标题显示“欢迎登录用户端”，其中“登录用户端”使用配置的强调色；
- 副标题显示“要出海·有货就能出海”；
- 表单包含手机号、验证码、获取验证码操作、协议说明和一个登录按钮；
- 《服务条款》和《隐私政策》通过系统浏览器打开；并且
- 表单保留键盘提交、清晰焦点、加载和错误状态。

渲染层通过现有的隔离 preload 桥接发送 `phone`、`verificationCode` 和 `remember: true`。桥接同时公开 `requestVerificationCode(phone)`。模拟 Provider 接受任意去除首尾空白后非空的手机号和验证码。模拟获取验证码不发起外部请求，只返回成功和重试间隔，使渲染层可走通真实 Provider 将使用的禁用和倒计时状态。

Electron 运行时使用 `SHOPWIS_CLIENT_BASE_URL` 覆盖网站根地址。`desktop.config.json` 使用 `https://client-test.shopwis.cn` 作为开发和打包后的回退值。配置加载要求 HTTPS 地址、移除结尾斜杠，并为公开 bootstrap 数据生成 `/user-agreement` 和 `/privacy-policy` 地址。生产接口提供后，同一根地址可作为默认 API 地址，但本提案不虚构接口路径。

个人中心、团队管理、设置、我的金币和退出登录都使用按钮。个人中心、团队管理和我的金币在目标页面存在前有意不产生导航副作用。设置继续打开现有设置面板；退出登录继续停止内置后端并返回登录表单。

## Data flow

主进程负责配置、URL 校验、模拟认证、会话持久化和外部导航策略。preload 公开带类型的 bootstrap、获取验证码、登录、账户和退出操作。渲染层负责字段状态、校验反馈、请求倒计时、协议链接呈现和提交进度。

认证 Provider 接口使渲染层与模拟实现相互隔离。网络 Provider 可以在内部增加服务端响应字段，而渲染层继续只消费规范化的成功或错误结果。

## Error handling

手机号或验证码为空时，渲染层和 IPC 输入解析都会拒绝请求。手机号为空时点击获取验证码会显示行内错误，并且不会开始倒计时。Provider 失败时保留用户输入，并在现有 live error 区域显示返回消息。

客户端根地址无效或不是 HTTPS 时，桌面应用会在启动阶段失败，而不是静默生成不安全链接。Electron 的 `setWindowOpenHandler` 继续只允许 HTTPS 外部导航。

## Testing

定向测试覆盖环境变量覆盖与回退 URL 生成、无效地址、模拟认证接受任意非空凭据、IPC 字段校验、协议链接目标、获取验证码状态、表单提交和账户菜单按钮语义。桌面端类型检查、渲染器构建、React 诊断和 Electron 视觉检查验证组装结果。

## Alternatives considered

**在手机号样式的渲染层背后保留邮箱和密码。**不采用，因为 UI 和 IPC 类型会描述不同凭据，真实接口到来时仍需再次进行跨进程迁移。

**绕过主进程，把表单作为渲染层内的直接导航。**不采用，因为这会绕过 Token 创建、会话持久化、权限和内置后端启动。

**在渲染层写死测试网站。**不采用，因为打包环境切换将需要修改源码，并可能误发测试协议链接。

## Verification

定向测试验证 URL 生成和校验、宽松模拟凭据、验证码倒计时、渲染层提交和账户菜单按钮语义。桌面端类型检查、lint、React 诊断、包构建和组装后的 Electron 运行验证从登录到工作区的完整流程。

## Consequences

宽松模拟会接受生产环境必须拒绝的凭据。该行为仅存在于显式 `mock` Provider 中，选择网络 Provider 后必须移除。

打包应用在没有对应环境变量的方式启动时无法获得运行时覆盖值，因此已校验的配置回退仍是打包分发所必需的。
